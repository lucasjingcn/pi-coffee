# pi-coffee 可靠性与成本证据改进方案

日期：2026-09-29。状态：5 项本地实施完成，验证通过；远端结果以提交对应的 GitHub Actions 为准。基线：`main` / `933c326e71c9d3e75f86355a98d9ff1211d458b1`，启动实施前工作树仅含本会话的方案文档。

## 目标与现有证据

让可信的本地编码代理在明确范围内协作；集成必须有可核查的验收证据，成本报告必须说明覆盖范围，派发必须服从用户授权和项目规则。保持现有模型、输出质量与人工审查要求。

- 当前版本 GitHub Linux CI 成功；本机 Node 24.19.0 执行 `npm run verify` 为 92 项、91 通过、1 失败，扩展和主代码类型检查通过。
- `tests/exec-timeout.test.mjs` 的 500ms 测试单独重跑仍失败；本机 `bash -lc` 启动约 510ms，`bash -c` 约 3ms，子进程 PID 尚未写出便超时。
- 验收命令目前只记录；`merge()` 不检查验收结果，Git 合并成功后可直接登记成功。
- 扩展在协调器请求失败时放行写入；任意脚本及动态路径不受完整检测。
- metrics 不掌握 Codex 全部使用量，仅按派发文本估算部分 token，不能证明总费用下降。
- skill、MCP instructions、playbook 中存在过宽派发及提交/推送措辞，需要统一。

本方案是这些待实施改进的权威清单；历史已完成工作继续记录在 `REVIEW.md`。

## 第一批：验收与写入保护（高风险）

### 1. 强制验收后集成

增加 `pi_verify`，执行派发时登记的验收命令并保存结果，而不是接受调用者填写 `passed: true`。可纯观察/调研的任务不要求生成验收文件，但代码集成必须有明确验收命令。

- 记录实际退出码、是否超时、受限输出、命令、worker 提交 SHA、目标分支 SHA、候选合并树标识及时间。
- 派发时保存主代理验收文件的内容摘要；集成前检查文件未被篡改。未声明修改范围的任务不得进入代码合并。
- 验证候选合并结果：以目标和 worker 的明确提交生成隔离候选工作树，在其中运行验收；不能只证明旧基线上的 worker 分支通过。
- 验证/合并期间拒绝并行派发修改、提交及改变被验证分支的控制请求；按规范化仓库身份串行集成。同一状态目录仍仅支持一个 daemon。
- worker 仍在工作、工作树有未提交内容、超范围改动、验收失败/超时、验收文件变化、提交或目标分支前移，均阻止合并。
- 合并前重查证据与分支状态；目标工作树有其他人的改动或正在 merge/rebase 时拒绝操作并说明原因，保留原文件及索引。
- 重启使未完成的验收失效；持久化记录仅作历史证据，不自动恢复合并许可。
- `pi_finish` 可以记录反馈或放弃，但成功结果必须引用通过的验收证据；有代码改动的成功结果还需集成记录。取消“Git merge 成功即业务成功”的推断。

验收：失败、超时、篡改验收、超范围写入、worker/目标前移、并发集成、重启、脏目标工作树，都有聚焦测试，证明失败时没有 Git 合并及成功登记副作用；正常候选验收通过后可集成。

### 2. 协调故障时阻止写入

- 对 edit/write/bash，协调器不可达、响应无效或锁申请失败时明确阻止调用；恢复连接后可以重试。
- edit/write 目标越出工作树，以及可识别的 shell 写目标越界时拒绝；对真实路径/符号链接做相应检查。
- 不以 bash 字面量扫描声称完整沙箱保护。保留执行测试和工具所需 shell 能力；任意脚本的越界写入仍需独立运行环境才能根本阻止。
- 不靠复杂 shell 解析器假装解决强隔离。第一批通过验收文件摘要、范围检查和候选验收阻止错误成果进入目标分支。

验收：连接拒绝、超时、错误响应、已占用锁及直接路径越界阻止工具执行；恢复后成功执行；正常读取可用。文档准确说明保护覆盖范围和绕过限制。

第一批预计涉及 manager、worktree、状态存储、MCP/HTTP、扩展及对应测试，必须一起核对序列化、错误返回和恢复行为。不能只修改工具说明。

## 第二批：平台适配、成本与派发规则

### 3. 修复 macOS 超时测试与执行合同

- 普通验证命令使用非登录 shell；保留 daemon 传入的 PATH 和凭据，若某操作确需登录环境则显式选择并记录，不隐式加载用户 shell 初始化。
- 超时测试将“子进程就绪”和“超时终止”分开验证，不通过单纯放宽时间或跳过断言换绿。
- 保留杀进程组、输出截断及超时及时返回的断言。
- CI 增加 macOS，与 Linux 一起运行受支持 Node 版本的 verify。

验收：本机原失败测试及 verify 通过；命令仍找到既定 node/pi；子进程被终止。远端 macOS CI 只有推送后才能验证，不把 workflow 文件存在当作 CI 通过。

### 4. 报真实成本覆盖范围

- 将“输出分工指标”与“费用证据”分开。保留 worker 输出量，但不把其与部分派发 token 的比值解释为省钱比例或质量评分。
- worker 统计涵盖活跃与历史任务，明确任务集合，避免关闭/GC 后漏算或重复算；失败及返工任务也进入统计。
- 缺失成本显示 unknown，并返回统计完整性；不能默认缺失费用为零。
- 支持登记带来源的主代理使用量/费用，标明手动录入、估算或实际提供方数据。主代理费用缺失或币种/范围不一致时，不给完整总费用和节省率。
- 真正对比需要相同验收、任务范围和成本口径，记录总耗时、返工与最终质量；不以更低质量或漏算审查消耗制造收益。

验收：历史任务、失败任务计入；未知值和手动/实测来源可区分；费用缺失时无虚构总额或节省率；状态重启及 GC 后统计一致。

### 5. 派发规则收敛

- 编排正文只留一份权威来源，安装 skill 和运行时 playbook 从其生成/加载；增加一致性检查。
- 优先服从用户指令与目标仓库 AGENTS.md。小修改直接完成；明确、独立、可验证且预计有收益的工作才考虑派发，不强制把所有实现交给 worker。
- 在 ai-gen 使用时落实其体量闸门：小改不派发，只有至少 3 个独立任务才考虑并行代理。
- 缺模型凭据时报告条件，继续可以独立完成的本地工作；不因 skill 要求调用工具而阻塞全部任务。
- 架构、安全、账务、权限、关键调试和最终验收由主代理负责。模型切换遵循用户批准及质量标准，不自动降低模型或生成规格。
- 删除“提交/推送是完成的默认收尾”等过宽措辞；提交、推送及外部写入分别服从当前项目规则和用户授权。
- 运行时提示词、MCP 描述、两份 README、安装后的本机 skill 同步更新，不只改一份文件。

验收：文档一致性检查；用明确的一行修复、三项独立实现、安全变更、缺凭据、仅本地整合场景检查派发和授权表述；实际效果在后续真实任务试跑中核查。

## 实施顺序与验证

1. 先完成 macOS 最小失败修复，建立可用本地验证基线。
2. 完成第一批的验收与写入保护，执行相关状态、Git、HTTP、扩展、恢复测试及 verify。
3. 完成成本报告与派发规则，同步文档和本机安装产物，执行对应测试及最终 verify。

上述是逻辑切片，不要求逐个机械拆提交。建议检查点为第一批安全行为完成、第二批统计与规则完成；这些检查点不授权提交、推送或发布。

每个切片先用失败用例证明问题，修改后运行直接相关测试；第一批跨控制接口/状态/Git 行为，立即运行项目 verify。最终以同一候选版本的 verify、离线 MCP 链路、类型检查和无凭据运行检查收尾，不重复运行未改变的等价检查。

验证代码默认使用临时 Git 仓库与离线模拟 worker，不发起收费模型调用。真实模型验证须具备所选模型凭据与费用授权，涵盖实际扩展加载、工具写入、候选验收及集成，独立报告。

第一批改动强耦合，由主会话串行设计和审查；不为凑并行数量拆任务。若后续确有至少 3 项独立、已授权且运行条件齐全的实现，可按项目规则派发。

## 完成审计与停止条件

- 本地完成：上述 5 项验收通过，文档与运行时合同一致，目标代码及安装 skill 来自同一候选版本，本地 daemon/代理/新 worker 的加载版本明确。
- 外部待验：真实模型的质量、总费用收益；GitHub macOS CI；远程部署。分别列明凭据、费用和推送/部署授权条件。
- 不把离线 smoke、HTTP 健康或新字段存在当作真实编码与省钱验收。
- 本地验收满足后停止；只剩外部待验时报告，不额外扩大重构或重复审查。

## 后续清单（不阻塞本次目标）

- 独立 OS 用户/容器运行 worker，隔离凭据和仓库访问，验收文件只读挂载；这是强隔离的单独设计，需明确兼容与数据访问合同。
- daemon 重启后的任务恢复、可靠主代理计费数据源和成本预算控制。
- 多用户/远程身份认证及细分权限；当前仅面向可信本地使用。
